# ssot-arch：核心抽象与架构设计

## 这个阶段解决什么问题

基于 `ssot` 的五条共同思维方式，在写业务单元与具体 VDM-SL 文件前，通过四步正向推导定下 `design/architecture/` 的**抽象边界、模块树、最小类型展开、连接面与状态不变量、生命周期嵌套以及依据与理由**。

```text
外部事实与系统需求 → [步骤 1：依据→抽象边界表] → [步骤 2：模块树与正交底座] → [步骤 3：持有与最小展开表] → [步骤 4：连接面与生命周期表]
```

示例设计的架构部分见 [`../ssot/references/example/design/architecture/`](../ssot/references/example/design/architecture/)。

---

## 步骤 1：从外部事实构建「依据 $\to$ 抽象边界」表

收集会改变架构形状的外部事实、约束、系统级需求与质量要求（不阅读或参考实现代码，不拿当前目录结构、调用步骤或技术选型当依据），构建抽象边界表：

| 外部事实 / 约束 / 质量要求（含来源） | 所以架构建立什么（“所以……”） | 留在抽象边界之外的实现/内部细节 | 为什么不选可信替代方案（「为什么」） |
|---|---|---|---|
| 例：上游在超时后仍可能已开始运行（来源：上游接口说明，证据见 `evidence/upstream-timeout.md`） | ``Run`StartOutcome`` 设 `<Unknown>` 分支，调用方经 ``Run`Status`` 按 ``Run`RequestNo`` 找回 | 超时重试的网络传输协议、客户端连接池、运行表的底层存储结构（放进 `reference/run-store.md`） | 不让调用方自己记下请求号与运行的对应：结果未知时调用方手里没有运行身份，只有提供方能按请求号找回 |
| 例：在上游可用时，同一请求号重复调用只产生一次运行（来源：示例需求） | ``Run`Start`` 按 ``Run`RequestNo`` 幂等，``Run`Runs.byRequest`` 记录请求号到运行的映射 | 幂等键在数据库中的索引方式与锁机制 | — |

**写作规则：**
- **依据（`## 依据`）**：每条一句话，写出“来源”，并接一句“所以……”，说明它让该模块多了或少了什么；质量要求写成“在〈环境〉下，〈刺激〉发生时，〈响应〉满足〈度量〉”（数值只在有真实出处时写）。影响全局的写根模块 `architecture/README.md`，只影响子模块的写子模块 `README.md`。
- **理由（`## 为什么`）**：引用依据与规格元素，说明为什么这样划分模块或连接，并在存在可信替代时写一句为什么不选它。

## 步骤 2：按两条轴划分模块树与正交底座

架构回答三个问题：**由什么组成**（有哪些模块，谁在谁里面）、**用什么组成**（模块由哪些核心元素拼成，经哪些连接相接）、**为什么**。

按两条独立的轴构建模块树：

1. **抽象层级轴（目录树深度）**：
   - 根模块（`architecture/`）粒度粗，子模块（`architecture/<child>/`）粒度细；
   - 子模块可 `imports` 祖先模块拥有的材料（如 `Attempt` `imports from Run types RunId`），**父模块绝不依赖子模块**；几个子模块共用的材料放在它们共同的父模块。
2. **模块三部分轴（每个模块的固定构成）**：
   - **外部连接**：导出给其他模块用的类型、值、函数与操作（`exports`）；
   - **核心代码**：本模块持有的类型、状态、不变量、纯函数与操作（`definitions`）；
   - **内部设计**：子模块目录，以及规格表达不了的本模块「语义」（包含关系、跨连接窗口、进程与恢复）。

**模块划分与正交性检验：**
- **只按抽象划分**：一组能对外陈述连接、对内隐藏决定的元素成为一个模块，不按篇幅或执行步骤拆分（如 `Attempt` 因“尝试记录只追加，只用到父模块的 `RunId`，父模块不需要知道记录怎样保存”而独立为子模块）。
- **正交底座零耦合**：各自独立表达一类外部边界或核心状态的并列架构模块（如来源能力、观察日志、受控写边界）保持彼此零 `import`；不在一个架构模块内部替业务去调用另一个架构模块做前置检查或引用管理，跨架构底座的串联归 `business/`。

## 步骤 3：构建「概念持有与最小展开」表

运用 `ssot` 的「视角、持有者与最小展开」思维，对每个候选概念判断其持有者及是否需要展开结构（`::` / `|`）：

| 候选概念 | 持有者模块 | 外部观察者（子模块或 `business/`）如何使用它 | 持有者内部写法与导出方式 |
|---|---|---|---|
| 例：运行身份 `RunId` | `Run` | `Attempt` 与 `Report` 只原样传给 `Record`、`Finish`，从不读取内部结构 | **保持 `= token`**，导出 `types RunId`（不带 `struct`） |
| 例：开始结局 `StartOutcome` 与 `Started` | `Run` | `Report` 必须在 `cases Start(request)` 中按 `Started \| <Rejected> \| <Unknown>` 分支处理并取出 `run` | **展开结构**（`Started :: run : RunId`、`StartOutcome = ...`），导出带 `struct` |
| 例：需要找回的运行判定 `Unresolved` | `Attempt` | 两个独立实现面对同一尝试序列必须算出同一待找回运行集合 | 在持有者 `Attempt` 中写成**显式纯函数** `Unresolved: seq of Entry -> set of RunId` |
| 反例：观察位置内部的 `stream + seqNo`、引用计数 `RefHolder`、写尝试内部阶段 `<Prepared> \| <Barriered>` | `Observation` / `Effect` | 外部观察者只调 `CheckBasis(basis)` 看 `<Fresh> \| <Stale>`、调 `Send(id)` 看 `<Accepted> \| <Rejected> \| <Unknown>`，从不读内部流序号或中间阶段 | **不展开**（位置与尝试身份在持有者内部也保持 `= token`；引用计数与两阶段落盘属于保护不变量的内部机制，不进设计） |

## 步骤 4：构建「连接面、状态不变量与生命周期」表

对每个持有状态的架构模块，设计其最小源头事实状态、连接点契约与生命周期嵌套：

| 连接面（`state`） | 源头事实分量（不放可由纯函数算出的派生字段） | 共享的状态不变量（`inv`） | 连接点（隐式 `operations`） | 准入条件与可观察结局（含失败恢复连接） | 生命周期锚点嵌套 |
|---|---|---|---|---|---|
| 例：`Run`Runs` | `byRequest : map RequestNo to RunId`<br/>`live : set of RunId` | `l subset rng b`（活着的运行都来自某个已登记请求） | `Start`、`Status`、`Finish` | `Start` 返回 `Started \| <Rejected> \| <Unknown>`；`<Unknown>` 时经 `Status` 找回 | 运行由 `Start` 加入 `live` 开始，由 `Finish` 移出 `live` 结束，嵌套在 `byRequest` 请求之内 |

**状态与连接设计核对项：**
1. **`inv`、`pre`、`post` 各管一事**：任何时刻都成立的性质写进类型或状态的 `inv`；允许调用的前提写进 `pre`（或跨模块调用的 `post` 准入子句）；调用前后的状态关系与输出要求写进 `post`。
2. **只列调用方必须区分处理的结局**：被拒绝只有一支 `<Rejected>`，不展开 `<QuotaExceeded> | <BadRequest> | <UpstreamBusy>` 等逐项原因。
3. **跨连接恢复写进场景与「语义」**：为可观察失败结局（如 `<Unknown>`）编写恢复场景操作（如 ``Run`Recover``），并将定时重试点、同进程包含关系与崩溃接管规则写进 `README.md` 的「语义」。

## 阶段产出与进入 `ssot-business` 的门控

完成以上四张表后，已确定 `architecture/` 的全部模块、类型、状态、连接签名与依据理由。确认以下门控全部成立后，进入阶段二 **`ssot-business`**：

1. 只看模块树与各 `README.md` 的负责范围，能直接说出系统由什么组成、用什么组成、谁在谁里面；
2. 凡是没有外部观察者分支匹配或读字段的类型，在持有它的架构模块内部也全部保持 `= token`，未混入引用计数、两阶段落盘或存储表结构等内部机制；
3. 并列的架构底座彼此零 `import` 耦合，父模块零依赖子模块，架构零引用业务；
4. 每条依据都有外部来源与“所以……”，每个连接面的操作都共享并维护同一条最小状态不变量。

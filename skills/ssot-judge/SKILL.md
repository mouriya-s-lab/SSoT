# ssot-judge：一个位置要不要往下写

准则在 `ssot` 第三节，本 skill 只给步骤与交付格式，不另立准则。

| 项 | 内容 |
|---|---|
| 输入 | 一个位置（元素 fqn，或两端元素 fqn 组成的一条连接），或使用者给的一份运行观测；使用者说明的项目阶段 |
| 可读 | `structure/*.c4` 里元素的 fqn、种类、标题、描述、标签与关系；`ssot render` 的 C4 图；已有契约模块的 `exports` 与已附着的需求编号；`behavior/` 下的模块名与它接进来的契约模块；`requirements.md` |
| 可改 | 无 |
| 可运行 | `ssot render <design>` |
| 输出 | 一份判断（见「交付」） |
| 上抛 | 位置本身在结构里不存在或放错了层：交回这个事实，给 `ssot-write-level` 与那一层的视图 id |

## 一、定位

看渲染图上这个位置：它是哪个框或哪个箭头，负责什么，与谁相连。观测指向的是一段行为时，找出这段行为经过哪些框与箭头。

## 二、回答三问

逐条写出答案，写不出就停在第一个答不出的地方：

1. **具体的担心。** 写出一句可以被证伪的话：“晚到的 launch 在闭包关闭之后仍被接纳”“同一个运行项的结束被写下两次”。泛泛的“这里很复杂”“可能有并发问题”不算。
2. **C4 与编译检查够不够。** 只靠图上的边界、普通的类型检查，以及使用者说明的测试与排错手段，能定位它吗？能，就停在原处，交付里写明靠什么定位。使用者没有说明测试与排错手段时，写明这一项未知，不替它推断。
3. **模型会揭露什么。** 往下写一层后，哪一个错误的盒子（`post` 允许了不该允许的结果）或错误的接线（两个盒子以不该有的先后交错）会被检查发现？写不出这个错误的样子，就不往下写。

## 三、定落点与精度

三问都答得出时：

- 担心只关于一个底层元素的端口承诺（数据上的前后关系）：落点是这个元素的 VDM 盒子。它还不是没有子元素、带 `#contract` 的元素时，先上抛给 `ssot-write-level`，`reason` 写明它要成为带 `#contract` 的底层元素。
- 担心关于几个元素之间的先后、交错、崩溃或停机之后的收束：落点是一张 Quint 接线图。写出它真正要调用的契约端口，以及只在接线里出现的行为一侧盒子（进程、在途请求、环境）。参与接线不等于要有 VDM 盒子：还没有盒子的元素，只有它自己的端口承诺也答得出三问时，才另落一个 VDM 盒子；否则它在接线里是行为一侧的盒子。
- 精度按使用者声明的阶段（`ssot` 第三节表格）：写明哪些端口只写签名、哪些地方要精确到什么性质，以及要接进来的环境（只接观测里真实出现过的）。

## 交付

- 位置与它在图上的样子；
- 三问的回答（停在哪一问，或三问全部的答案）；
- 结论：停在原处，或落点（元素 fqn 的 VDM 盒子 / Quint 模块名与接进来的盒子）与精度；
- 需要先做的上抛（如有）。

判断不落盘；被采纳时，它体现为接下来写下的载体。

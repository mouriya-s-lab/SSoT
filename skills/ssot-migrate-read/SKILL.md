# ssot-migrate-read：代读旧文档的一个区域

旧设计文档由 `ssot:reader` 代读。你不读旧文档：它的字段、记录形状、处理先后、校验与错误处理会把你带进细节。你只读代读者写下的文件。

`scope` 是旧文档的一个区域：一个概念所在的那一节，或一个没有标题的文件。`.tmp/ssot-migrate/regions.md` 还不存在时，先做第一步。

## 五项

| 项 | 内容 |
|---|---|
| 可读 | 代读者在 `.tmp/ssot-migrate/` 下写的文件；`structure/*.c4` 里元素的 fqn 与标题（只用来写交接里的建议落点）。不读旧文档，不读 `contract/`、`behavior/` |
| 可改 | 无。只有代读者写 `.tmp/ssot-migrate/`；你不写设计目录 |
| 工具工作集 | 无：本叶子不运行 `ssot` 检查 |
| 末尾评审 | 无：交出的需求由 `ssot-draft-requirement` 逐条论证，那里再判断 |
| 向上修正 | 不适用：本叶子不写设计。代读者交出的概念与现有设计冲突时，不在这里判断，原样交给 `ssot-draft-requirement` |

## 一、区域清单（只在第一次做）

按 `ssot` 第七节派 `ssot:reader`（`isolated: false`，留着供追问），只告诉它：旧文档的位置、迁移的范围（用户的原话）、要它先写区域清单 `.tmp/ssot-migrate/regions.md`：每个区域一行，写文件、标题与一句话的主题，不写内容。

## 二、代读一个区域

本会话里第一步派出的代读者还在，就给它发消息；不在（例如这是新的一次调用），就按第一步的方式新派一个，只告诉它旧文档的位置、`.tmp/ssot-migrate/regions.md` 与要读的区域。消息里给出区域编号与输出目录 `.tmp/ssot-migrate/<区域编号>/`。它写两个文件：

- `concepts.md`：概念备忘。每个对象是什么、从哪来或为什么需要、守住什么、和谁什么关系，附出处与读到的范围；
- `requirements.md`：原文明确写出的需求、外部事实与约束，一条一项，原文摘录并附出处，标明是需求、外部事实还是约束。

只读这两个文件，不读代读者的会话记录。有概念问题时追问它（它写成同目录下的 `reply-<编号>.md`）：只问某个对象是什么、为什么需要、和谁什么关系、原文有没有作某个划分。不问细节，不问“这样划分对吗”。

它说“原文没有”时，看它写明的读到的范围；没读到的不能当作没有。

## 三、交接

交付：区域编号、两个文件的路径、摘录里的需求条数与外部事实条数，以及下一项前沿 `{skill: ssot-draft-requirement, scope: .tmp/ssot-migrate/<区域编号>/requirements.md, reason: 迁移区域 <编号>}`。外部事实在那里写成承担它的元素的依据。

本次调用结束前，删掉拷入项目的 `.omp/agents/ssot-reader.md`；下次调用需要时再拷。

# 行为的写法（Quint）

`ssot-write-behavior` 照这里写一个可运行的 Quint 模块，`ssot-verify-behavior` 照这里判断。例子取自 soroi 示例设计（[`../../ssot/references/example/design/`](../../ssot/references/example/design/)）的 `design/behavior/engine.qnt`。

## 一、行为只写跨连接的次序

行为持有：跨连接的先后、交错、受理窗口、停机与崩溃收束、活性，以及必须走到的情形（覆盖目标）。集合上的需求在这里完整表达：对有界候选集合里的每个元素都成立，而不是拿一个代表元走通一次。时钟、进程、崩溃、重启与调度只在这里出现，契约里不模拟它们。

| 不写进行为 | 持有者 |
|---|---|
| 类型、操作、函数，以及与它们同名的声明 | 契约：经 `.gen/contract.qnt` 引用 |
| 一次调用前后数据满足什么（`pre`/`post`/`inv`）、判定函数的结果 | 契约：回放时在 VDM 里检查 |
| 元素与依赖方向 | 结构 |

## 二、模块与引用

每个行为文件一个模块，模块名与文件名相同。契约的名字全部经生成的模块引用，嫌限定名长时起别名：

```quint
module engine {
  import contract.* from "../.gen/contract"
  import Vdm.* from "../.gen/contract"
  import soroi_store as Store from "../.gen/contract"
  import soroi_workspace as Ws from "../.gen/contract"
```

`.gen/contract.qnt` 由 `ssot gen` 写出，不手改。行为里不声明与契约的类型、操作或函数同名的东西；行为自己的概念（进程的阶段、请求的进度）在本模块定义一次，别处只引用。

## 三、Call 变量

可运行模块恰有一个类型为 `Call` 的状态变量。代表契约调用的步骤调用一次，把生成的 `Call` 变体写进它，参数和结果都在载荷里；不是契约调用的步骤写 `NoCall`：

```quint
  var lastCall: Call

  action commit(call: Call): bool = all {
    lastCall' = call,
    store' = storeAfter(store, call),
    ws' = workspaceAfter(ws, call),
  }

  // 闭包过程取得本运行项的开始事实
  commit(soroi_store(Store::readStart({ rt: rt, result: startFact })))
  // 不调用契约的步骤
  commit(NoCall)
```

契约改名、删除操作或改签名时，Quint 的类型检查直接失败。契约状态只能经契约调用改变：某一步改了生成的状态变量，而 `lastCall` 不是那个模块的调用，工具报错。

## 四、契约状态只用生成类型，用 `initial` 初始化

可运行模块调用了哪个有状态模块的操作，就为它恰好声明一个生成类型的变量，并在每一步按那个操作的 `post` 更新它：

```quint
  var store: Store::Records
  var ws: Ws::Closures
```

`init` 把每个契约状态变量直接赋值为生成的初态，不手写同值的字面量：

```quint
  action init = all {
    store' = Store::initial,
    ws' = Ws::initial,
    lastCall' = NoCall,
    // 其余变量只持有过程、请求与调度状态
    ...
  }
```

每次契约调用都被回放：取调用前后的状态与载荷，在定义该操作的 VDM 模块里对原样规格求 `pre` 与 `post`，并检查这个操作只读或不写的分量前后相等。所以：

- 按 `post` 更新状态是第二份手写，它受检，但只在采样到的轨迹上受检，不是证明。只读操作的分支照样写成状态不变（`readStart(_) => s`），回放会检查它。
- 只复述某个 `pre` 的 Quint 不变式可以删掉，回放会检查 `pre`。
- 契约状态已经持有的事实，从契约状态变量里读；不再另设一个变量记同一件事。守卫要判断“闭包已关闭”，读 `ws.closed`，不另记一个关闭锚点；两份锚点会各自更新，表述就分裂了。其余变量只放契约状态之外的东西：进程内的阶段、在途的请求、调度与重启后保留的进度。

## 五、不重写契约的事实

逐个看行为里的定义、守卫、取值与不变式，问它是不是在重算契约已经决定的事：一个判定函数的结果、一条 `inv`、某个操作的 `pre`/`post`。是的话，行为不再写一份：

- **载荷取值不在行为里判定。** 行为只决定什么时候调用、调用之后走哪条路；载荷与结果取类型允许的值（`nondet` 取，或取一个只被搬运的代表值），合不合法交给被调用操作的 `pre`/`post`，由回放检查。
- **只活在纯函数里的事实要回到契约。** 回放只求被调用操作的 `pre`/`post`，从不求值纯函数。一条事实只写在某个纯函数里、行为又照着它另算一遍，两份就都没有检查：把它写进被调用操作的 `pre`/`post`，或给纯函数写上 `post` 让证明义务去查，不在 Quint 里抄一份。
- **冗余字段在契约里删掉。** 一个值能由契约里别的值决定（执行的角色由它携带的闭包参数决定），行为却要另选一次，问题在契约的形状：删掉冗余的字段，让行为没有可选的东西。

两种典型的重写（反例，示例设计里没有）：契约用 `roleOf(ToolArgs) = <Tool>` 决定执行的角色，行为又在工具步骤里自己选 `Ws::Role_Tool`；契约的派生模块用纯函数判定哪些旧记录可以沿用，行为又写一个同义的 `reusable` 去选沿用对象。两处都是同一事实的两份手写，而且都没有任何检查把它们绑在一起。

## 六、次序怎样写

- **参与者只用自己知道的值。** 每一步的守卫与载荷只用这个参与者本来就知道的值：它自己的过程状态，或前一个连接交给它的值（闭包过程用 `writeStart` 返回的 `rt`）。不读另一个参与者的内部变量。
- **每个结局都有去处。** 被调连接的结果是并类型时，每个变体都有产生它的步骤，也有接住它之后的路：`Launch_Result_ExecRef`、`Launch_Result_Rejected`、`Launch_Result_Failure` 各有一步，失败一支走到停机或拒绝。
- **集合用有界常量完整表达。** `pure val RUNS = Set("r1", "r2")` 这类常量给出候选集合，`nondet r = RUNS.oneOf()` 让每个元素都可能被选到，不变式对集合里的每个元素都成立。
- **时钟与崩溃是行为里的事件。** 崩溃写成一步：进程内的变量（`dmn`）丢失，跨崩溃保留的事实（契约状态、执行边界里的进度）留下；重启后的接管次序写成后续的步骤。
- **只用于不变式的变量（ghost）不进守卫。** 它们记“被排除的事件是否发生过”，只给 `safety` 用。

## 七、safety 与覆盖目标

声明了 `init` 与 `step` 两个 action 的模块是可运行模块，它必须有一个 `val safety`，即不变式的合取。模拟中 `safety` 被违反即报错。

随机模拟不保证走到少见的交错。每个名字以 `witness` 开头的 `val` 都是必须覆盖的情形，工具对它做一次以它为终点的定向模拟，走不到时检查失败：

```quint
  // 已退出进程发出的在途 launch，在它的闭包已关闭之后才得到回复
  val witnessLateLaunchAnswered = ghost.lateLaunchAnswered
  // 派生运行至少为一个旧记录追加了 Ref：路径约 25 步，单独放宽步数
  val witnessRefAppended = referenceSources != Set()
  pure val maxSteps_witnessRefAppended = 60
```

- 为每条需要证明“确实走到过”的路径写一个覆盖目标：每种停机触发、自然完成、派生、崩溃后的重新附着，以及没被普通模拟稳定走到的结局变体。
- 某个目标需要的步数多于默认值时，在同一模块声明 `pure val maxSteps_<目标名> = <正整数字面量>`。它必须是字面量，不能是计算出来的表达式。
- 定向模拟仍是抽样，预算按样本数而不是墙钟。目标很少出现时，调整调度频率（示例用 `nondet roll = 1.to(16).oneOf()` 放慢外部事件与失败），或放宽这个目标的步数。
- 回放统计每个并类型结果的每个变体出现了几次，出现 0 次的列为未覆盖。它不拒绝设计，但让 `ssot status` 把这个行为模块列为“仍有未覆盖结局”的前沿：判断那个变体是缺路径、缺覆盖目标，还是契约多列了一个在需求下不会发生的结局（后者回到契约删掉它）。

## 八、工具会拒绝什么

`ssot check` 把下面这些当错误：

| 规则 | 拒绝什么 |
|---|---|
| `compile.quint` | Quint 的语法与类型错误，包括载荷不符合契约签名 |
| `behavior.names` | 声明了与契约同名的类型、操作或函数 |
| `behavior.call` | 没有或有多个 `Call` 状态变量；可运行模块缺 `safety`；`maxSteps_<目标名>` 不是正整数字面量的 `pure val`；契约状态变量变了而 `lastCall` 不是那个模块的调用 |
| `behavior.init` | `init` 没有把契约状态变量直接赋值为 `<别名>::initial` |
| `behavior.run` | 模拟中 `safety` 被违反 |
| `replay.pre` / `replay.post` / `replay.inv` / `replay.eval` | 回放的一次调用在契约下 `pre` 或 `post` 为假、不变式被破坏或求值出错 |
| `replay.frame` | 回放的一次调用改动了操作只读或不写的分量 |
| `replay.initial` | 轨迹的初态不等于契约的初态 |
| `replay.incomplete` | 不透明值无法构造、缺少契约状态变量、覆盖目标没有走到：验证不完整 |

`replay.outcome`（结局变体的出现次数）只是提示。检查被墙钟截止打断时报 `resource.deadline`：没有错误级诊断时 `check` 以 3 退出，表示验证没有完成、不是设计被拒绝，重跑或调整覆盖目标的步数与调度，而不是改设计去迁就；同时有错误时以 1 退出。

## 九、评审时怎么判

只评本模块，带着 `ssot check --scope` 的结果逐项判断：

1. **名字只在持有者定义。** 契约的名字全部经生成模块引用，没有同义的另一份定义；行为自己的概念只定义一次。`behavior.names` 拒绝与契约同名的声明，`vocab.slots` 拒绝结构槽位里出现契约或行为的名字；初态与契约状态的修改由 `behavior.init`、`replay.initial` 与 `behavior.call` 确证，评审只看工具确证不了的同义重述。
2. **不重写契约事实。** 对照第四、五节：契约状态只用生成类型、用 `initial` 初始化；没有与契约状态并行的锚点；守卫、取值与不变式没有重算判定函数、`inv` 或 `pre`/`post` 已经决定的事。
3. **集合完整表达。** 需求涉及的集合由有界常量给出，每个元素都可能被选到，不变式对全集成立。
4. **参与者只用自己知道的值。** 逐个看守卫与载荷，值来自本参与者的状态或前一个连接的交付。
5. **每个结局都有处理。** 每个被调连接的每个结局变体都有路；`replay.outcome` 里出现 0 次的变体，判断是缺路径还是缺覆盖目标。
6. **时钟、崩溃、重启、调度在行为里表达。** 这些语义确实被写成了步骤与窗口，没有遗漏，也没有漏进契约。
7. **每个元素都服务需求。** 每个变量、步骤、守卫与覆盖目标都能指出它服务的需求；只为让检查通过或让覆盖目标走到而加的步骤与守卫，删掉。
